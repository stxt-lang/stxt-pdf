# Structure of a document

A document describes a **box tree** with elements (`Block`, `Stack`, `Grid`, `Text`, etc.) that accept only the
properties that make sense in them. The engine computes the position and the size of each box in a sequence of
fixed-size **pages**, splits across pages what does not fit and writes the result to a PDF.

## Conventions

- **Measurements are in typographic points** (1 pt = 1/72 of an inch) **or in millimeters** (`12mm`), which are turned
  into points when the document is read. An A4 page measures 210 × 297 mm, 595.28 × 841.89 pt.
- **The names of nodes and values are in English**: `Margin`, `Overlay`, `Edges: open`. The text of a `Text`
  can be in any language.
- **The axes:** *horizontal* is that of `Width` and *left/right*, and *vertical*, that of `Height` and *top/bottom*. Writing
  is always horizontal, from left to right.
- **The four boxes of a box** ([The box](box.md#the-four-boxes)): content, padding, border and margin.
  Unless stated otherwise, positions and sizes are those of the **border box**.

## Elements

Each element accepts only the children that make sense in it: its properties and, if it is a container, other elements. This
is defined by the [schema](#schema), so a property out of place (`Column sizes` in a `Stack`, `Offset` in a `Block`) is
an error when the document is read, in the editor too.

The root is `Document`, with exactly one `Page`, one `Title` and one `Language`, an optional `Styles` with the reusable
rules ([Styles](styles.md)), the `Page overlay` elements of the whole document and one or more `Section` with the content
([Document](../components/document.md)). There is no loose content: everything that is laid out goes inside a section. The
rules can also come from a separate styles document ([Styles](styles.md#separate-styles-document)).

| Element | What it is | Contains |
|---|---|---|
| `Section` | Part of the document with its `Page`, its `Page overlay` elements and its numbering ([Document](../components/document.md#section)) | Elements, and its `Page` |
| `Block` | Box that stacks its children vertically ([Block](../components/block.md)) | Elements |
| `Stack` | Places its items in lines ([Stack](../components/stack.md)) | `Item`, `Overlay` and `Page overlay` |
| `Grid` | Places its items in a grid ([Grid](../components/grid.md)) | `Area`, `Overlay` and `Page overlay` |
| `Text` | Standalone text: a label, a figure, a line of a header ([Text](../components/text.md)) | Its text, in the value or in `Content`, without blank lines |
| `Paragraph` | A paragraph of the content ([Text](../components/text.md#paragraph)) | Its text, in the value or in `Content`, without blank lines |
| `Heading 1` to `Heading 6` | Heading of level 1 to 6 ([Headings](../components/heading.md)) | One or more `Text` |
| `List` | List with markers or numbered ([List](../components/list.md)) | One or more `List item` |
| `List item` | Item of a `List`: a block with its marker | Elements, except headings |
| `Table` | Table with a header and a footer that repeat on each page ([Table](../components/table.md)) | `Header rows`, `Body` and `Footer rows`, in that order |
| `Header rows`, `Body`, `Footer rows` | Header, body and footer of a `Table` | One or more `Row` |
| `Row` | Row of a table | One or more `Cell` |
| `Cell` | Cell: a text or a block | Its text in the value, or elements except headings |
| `Columns` | Block whose content flows through several columns ([Columns](../components/columns.md)) | In-flow elements |
| `Markdown` | Content written in Markdown ([Markdown](../components/markdown.md)) | Its text in `Content` |
| `Footnote` | Footnote, which the engine places at the bottom of the page of its call `[^id]` ([Footnote](../components/footnote.md)) | `Paragraph`, `Text`, `Markdown`, `List`, `Table` and `Block` |
| `Image` | PNG, JPEG or SVG image, or a page of a PDF ([Image](../components/image.md)) | Nothing: the path goes in the value |
| `Barcode` | QR code or barcode generated from its data ([Barcode](../components/barcode.md)) | Its data, in the value or in `Content` |
| `Table of contents` | Automatic table of contents ([Table of contents](../components/table-of-contents.md)) | Nothing: the entries are generated by the engine |
| `Frame` | Block that is shifted without moving its siblings ([positioned elements](../components/frame-and-overlays.md)) | Elements |
| `Overlay` | Out-of-flow block, placed in its reference container | Elements |
| `Page overlay` | Out-of-flow block, placed in the page area of the pages given by `Pages` | Elements |
| `Item` | Item of a `Stack`: how it grows, shrinks and is aligned | Exactly one in-flow element |
| `Area` | Item of a `Grid`: the area it takes up and how it is aligned | Exactly one in-flow element |

**Elements** are all except `Section`, `Item`, `Area`, `Header rows`, `Body`, `Footer rows` and `Row`, and each one is a
box of the [tree](#the-box-tree). **In-flow elements** are those that can be an item: all except `Overlay` and
`Page overlay`, which leave the flow, and `List item` and `Cell`, which only go in a `List` and in a `Row`.

`Item` and `Area` are not boxes: they are **wrappers** that add to the element what only makes sense inside its
container. Neither are `Header rows`, `Body`, `Footer rows` and `Row`: they group the cells, which are boxes. A `Row` with `Id`
or `Box` also has a band that is painted under its cells ([Table](../components/table.md#rows)), but it does not
take up space.

> **Decision:** `Item` and `Area` are wrappers with exactly one in-flow element (`SINGLE_ELEMENT`): size,
> margins and `Id` go in the element, and each item is a single box. Every in-flow child of a `Stack` is an `Item`, and of
> a `Grid`, an `Area`, even if it declares nothing. *Rejected alternative:* wrappers that are boxes with several children, or
> accepting loose elements and the wrapper only when it is needed (two ways of writing the same thing).

### Properties and groups

Properties are grouped by meaning: `Box` ([the box](box.md)), `Typography` ([the text](typography.md),
which is inherited) and `Break` ([page breaks](breaks.md)). Each group appears at most once per element, and each
property, at most once per group. Outside the groups is what defines the element: the
[element properties](#element-properties) and those specific to each one (`Gap` of `Stack`, `Offset` of `Overlay` or
`Marker` of `List`).

```
Text: Quarterly results
    Id: title
    Box:
        Margin: 0 0 16 0
    Typography:
        Bold: true
        Size: 20
    Break:
        Keep with next: true
```

> **Decision:** inside a group the names are short (`Size`, `Align`, `Before`) except where they clash with another node:
> `Line breaking` and not `Wrap`, which belongs to `Stack` and is something else, because a name is the same node in the whole schema.

> **Decision:** a name says what the thing is in the document and not the algorithm that lays it out (`Columns`, `Balance`), and
> when publishing or a word processor already has a well-known one, that one is used (`Style` for a named style,
> `Table of contents` and `TOC 1` to `TOC 6`, `Row header`, `Corner radius`). The axes are named by their direction on the page
> (`Horizontal`, `Vertical`) and not by their role, and there are no two nearly identical names with different meanings (hence
> `Table of contents` and not `Contents`, which was confused with `Content`). *Rejected alternative:* names of the
> mechanism (`Multicol`, `Relative`, `Absolute`, `Fixed`, `Main axis`), which only those who already know it understand.

### Element properties

| Property | Values | Default | Elements | Notes |
|---|---|---|---|---|
| `Id` | text | none | Elements and `Section` | Identifier for references, links, `For id` rules and messages. Unique in the document (`DUPLICATE_ID`). |
| `Style` | names separated by spaces | none | Elements and `Section` | The `For style` rules with those names apply to it ([Styles](styles.md)). Each style needs its rule and is not repeated. |
| `In table of contents` | `true`, `false` | `true` | Headings | Whether the heading has an entry in the tables of contents ([Headings](../components/heading.md#outside-the-table-of-contents)). |
| `Link` | `https://...`, `http://...`, `mailto:...` or `#id` | none | Elements except `Markdown` and `Table of contents` | Makes the whole box clickable ([Links](links.md)). It is not inherited and does not change the appearance. |
| `Isolate margins` | boolean | `false` | `Block`, `Frame` | Stops margin merging with the children ([Block](../components/block.md#margin-merging)). |

## Order and text

**Order matters.** The engine places the elements in the order in which they appear. The order of the properties, and their position
relative to the elements, does not matter.

**Inline or block text.** `Text: one line` carries the text in its value. Long text goes in a
`Content >>` block, without escape characters. A `Text` has one of the two, never both ([Text](../components/text.md)).

## Example

```
Document (dev.stxt.pdf):
    Language: en
    Title: Report
    Page:
        Paper: A4
        Margin: 40
    Styles:
        For element: Document
            Typography:
                Font: IBM Plex Sans
                Size: 10
    Section:
        Text: A title
            Id: title
            Typography:
                Size: 20
        Stack:
            Id: body
            Gap: 10
            Item:
                Grow: 1
                Block:
                    Paragraph: First paragraph.
                    Paragraph: Second paragraph.
            Item:
                Block:
                    Box:
                        Width: 100
                        Background: #F1EFE8
```

## The box tree

Each element is a box, and each section is the root of its pages, with the page area of each one. `Item` and `Area` do not
create a box: their properties pass to the element they wrap. There are no anonymous boxes, because text always goes in its
own `Text`.

Each element decides **how it places its children**:

| Element | Places its in-flow children |
|---|---|
| `Section` (the page area), `Block`, `Frame`, `Overlay`, `Page overlay`, headings, `List`, `List item`, `Markdown`, `Table of contents`, `Cell` with elements | In block flow ([Block](../components/block.md#block-flow)) |
| `Stack` | In lines ([Stack](../components/stack.md)) |
| `Grid`, `Table` | In a grid ([Grid](../components/grid.md), [Table](../components/table.md)) |
| `Columns` | In columns, each one in block flow ([Columns](../components/columns.md)) |
| `Text`, `Paragraph`, `Cell` with a value | No children: it breaks its text into lines ([Typography](typography.md#line-breaking)) |
| `Image`, `Barcode` | No children: its content is the image ([Image](../components/image.md), [Barcode](../components/barcode.md)) |

**Participation.** How a box takes part in its parent is decided by the parent: inside a block it is a stacked block, and inside
a `Stack` or a `Grid`, an item. `Overlay` and `Page overlay` leave the flow, and a `Frame` takes part like any box and
is then shifted.

## Schema

The schema is [`src/main/resources/stxt/dev.stxt.pdf.stxt`](../../../../src/main/resources/stxt/dev.stxt.pdf.stxt), with the
namespace `dev.stxt.pdf`. It defines each node only once and the children it accepts. The same name is the same node in the whole
schema (the `Width` of `Page` and that of `Box`), so `Gap`, `Horizontal` and `Vertical` have the same
values everywhere they go. What is not valid in one of them is an engine error.

This summary gives the children of each node with children. If it differs from the file, the file prevails. Each property appears at most
once, and the elements, as many times as needed.

| Node | Children |
|---|---|
| `Document` | `Page`, `Title` and `Language` (exactly one of each), `Styles`; `Page overlay`, `Section` (at least one) |
| `Section` | `Id`, `Style`, `Page`, `Page numbering`, `Page number format`, `Start`, `Inherit page overlays`, `Begin on`, `Footnote numbering`, `Footnote number format`; elements |
| `Page` | `Paper`, `Orientation`, `Width`, `Height`, `Margin`, `Mirror margins` |
| `Styles` | `Named color`, `For element`, `For style`, `For id`, `For column`. Child of `Document` or root of a separate styles document |
| `For element`, `For style`, `For id`, `For column` | `Box`, `Typography`, `Break` |
| `Block` | `Id`, `Style`, `Link`, `Box`, `Typography`, `Break`, `Isolate margins`, `Rotate`; elements |
| `Stack` | `Id`, `Style`, `Link`, `Box`, `Typography`, `Break`, `Direction`, `Wrap`, `Gap`, `Horizontal`, `Vertical`, `Line distribution`; `Item`, `Overlay`, `Page overlay` |
| `Grid` | `Id`, `Style`, `Link`, `Box`, `Typography`, `Break`, `Column sizes`, `Row sizes`, `Gap`, `Areas`, `Flow`, `Horizontal`, `Vertical`; `Area`, `Overlay`, `Page overlay` |
| `Text`, `Paragraph` | `Id`, `Style`, `Link`, `Box`, `Typography`, `Break`, `Content`, `Rotate` |
| `Heading 1` to `Heading 6` | `Id`, `Style`, `Link`, `In table of contents`, `Box`, `Typography`; `Text` (at least one) |
| `List` | `Id`, `Style`, `Link`, `Box`, `Typography`, `Break`, `Marker` (required), `Start`; `List item` (at least one) |
| `List item` | `Id`, `Style`, `Link`, `Box`, `Typography`, `Break`, `Number`; elements except headings (at least one) |
| `Table` | `Id`, `Style`, `Link`, `Box`, `Typography`, `Break`, `Column sizes` (required), `Column align`, `Gap`; `Header rows`, `Body` (required), `Footer rows` |
| `Header rows`, `Body`, `Footer rows` | `Row` (at least one) |
| `Row` | `Id`, `Style`, `Box` (appearance only), `Typography`, `Break`; `Cell` (at least one) |
| `Cell` | `Id`, `Style`, `Link`, `Box`, `Typography`, `Span`, `Row header`; elements except headings |
| `Columns` | `Id`, `Style`, `Link`, `Box`, `Typography`, `Break`, `Count`, `Min column width`, `Gap`, `Separator`, `Separator color`, `Balance`; in-flow elements |
| `Markdown` | `Id`, `Style`, `Box`, `Typography`, `Break`, `Bullet markers`, `Number markers`, `Table columns`, `Content` (required) |
| `Footnote` | `Id` (required), `Style`, `Box`, `Typography`; `Paragraph`, `Text`, `Markdown`, `List`, `Table`, `Block` |
| `Table of contents` | `Id`, `Style`, `Box`, `Typography`, `Break`, `Levels`, `Leader` |
| `Image` | `Id`, `Style`, `Link`, `Box`, `Break`, `Alt`, `Fit`, `Pdf page`, `Rotate` |
| `Barcode` | `Id`, `Style`, `Link`, `Box`, `Typography` (only `Color`), `Break`, `Alt` (required), `Format`, `Error correction`, `Rotate`, `Content` |
| `Frame` | `Id`, `Style`, `Link`, `Box`, `Typography`, `Break`, `Isolate margins`, `Offset`, `Layer`, `Rotate`, `Rotate origin`; elements |
| `Overlay` | `Id`, `Style`, `Link`, `Box`, `Typography`, `Offset`, `Layer`, `Rotate`, `Rotate origin`; elements |
| `Page overlay` | `Id`, `Style`, `Link`, `Box`, `Typography`, `Offset`, `Layer`, `Pages`, `Rotate`, `Rotate origin`; elements |
| `Item` | `Grow`, `Shrink`, `Base size`, `Horizontal`, `Vertical`, `Layer`; one in-flow element |
| `Area` | `Horizontal`, `Vertical`, `Layer`; one in-flow element |
| `Box` | `Width`, `Height`, `Min width`, `Max width`, `Min height`, `Max height`, `Aspect ratio`, `Margin`, `Padding`, `Border`, `Border color`, `Corner radius`, `Background`, `Overflow` |
| `Typography` | `Font`, `Code font`, `Bold`, `Weight`, `Italic`, `Size`, `Min size`, `Line height`, `Align`, `Color`, `Line breaking`, `Hyphenate`, `Markup`, `Case`, `Letter spacing`, `Small caps`, `Ligatures`, `Kerning`, `Preformatted`, `Tab size`, `Numbered`, `Number format`, `Number label`, `Widows`, `Orphans`, `Language` |
| `Break` | `Before`, `After`, `Keep with next`, `Keep with previous`, `Keep together`, `Edges` |

*Elements* are `Block`, `Stack`, `Grid`, `Text`, `Paragraph`, the headings, `List`, `Table`, `Columns`, `Markdown`,
`Table of contents`, `Image`, `Barcode`, `Frame`, `Overlay` and `Page overlay`.
`Footnote` goes wherever the in-flow elements go (except in `Item` and `Area`), but it is not a box of that place: it goes at the bottom of the page. *In-flow elements* are all except `Overlay` and `Page overlay`.

Only the properties (not the groups), `Text`, `Paragraph`, `Cell`, `Image`, `Barcode`, `Area`, the `Styles` rules and `Named color` carry a value on their line.
`Block: something` is an error. `Content` always goes in a `>>` block, and `Areas`, inline or in a block. What the schema cannot
express (that `Page` declares its size in a single way, that an `Item` has exactly one element, the order of the
parts of a table) is checked by the engine, with the codes of [Errors](errors.md).

## What is not supported

- **Loose text between boxes:** text always goes in a `Text`, a `Paragraph` or a `Cell`.
- **Text and blocks on the same line:** an element places its children in a single way.
- **Vertical writing** or right-to-left writing.
