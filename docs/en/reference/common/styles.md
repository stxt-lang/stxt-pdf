# Reusable rules: `Styles`

`Styles`, an optional child of `Document` (at most one), declares once properties that apply by default to many
elements, and the [named colors](#named-colors) of the document. The same rules and colors can also be in a [separate
styles document](#separate-styles-document), or in [several](#several-styles-documents). There is no cascade: the rules give default values to the elements of a
type, of a style or with an `Id`, and the element can override them.

## Rules

| Rule | Value | Applies to |
|---|---|---|
| `For element` | `Document` | the root: its `Typography` is the base that all boxes inherit. Only allows `Typography` |
| `For element` | name of a box element (`Block`, `Text` or `Heading 1`) | all the elements of that type |
| `For element` | an element generated by the engine: `Code block`, `TOC 1` to `TOC 6` or `Footnotes` | the code blocks of a `Markdown` ([Markdown](../components/markdown.md#code)), the entries of a `Table of contents` ([Table of contents](../components/table-of-contents.md#style)) or the footnote area of each page ([Footnote](../components/footnote.md#the-footnote-area-footnotes)). They are not written in the document |
| `For element` | a position in a table: `Header cell`, `Body cell`, `Footer cell`, `Odd row cell` or `Even row cell` | the cells of a `Table` in that position ([Table](../components/table.md#cell-style)) |
| `For style` | a name, without spaces | the elements with that name in their `Style`, the cells of a `Row` with it in its `Style` and the styled runs `[text]{name}` ([Text formatting](text-formatting.md#styled-runs)) |
| `For id` | an `Id`, without spaces | the element with that `Id` |
| `For column` | a column (`3`) or a range of columns (`2 4`, both included) | the cells of a `Table` that **start** in those columns |

Each rule allows the `Box`, `Typography` and `Break` groups, at most one of each, and the
[element properties](#element-properties) that say how an element looks or how it distributes its content (`Gap`,
`Column sizes`, `Fit`, `Marker`...), at most one of each. A rule written inside another is a
[nested rule](#nested-rules): it applies to the elements that are inside an element the outer one applies to.

```
Styles:
    For element: Text
        Typography:
            Align: justify
    For style: note
        Box:
            Background: #F1EFE8
            Padding: 8
    For id: title
        Typography:
            Size: 20
            Bold: true
Text: Quarterly results
    Id: title
    Typography:
        Align: left
Text: A side note.
    Style: note
```

## Element properties

A rule also gives properties of an element itself, as if the element declared them:

```
Styles:
    For style: dish
        Gap: 12
    For element: Image
        Fit: fill
Stack:
    Style: dish
    Item:
        Grow: 1
        Text: Red prawn croquettes
    Item:
        Text: €9.50
Image: photos/room.jpg
```

They are those of appearance and distribution. The rule that applies to an element of that type allows them:

| Element | Properties in a rule |
|---|---|
| `Stack` | `Direction`, `Wrap`, `Gap`, `Horizontal`, `Vertical`, `Line distribution`, `Split items` |
| `Grid` | `Column sizes`, `Row sizes`, `Gap`, `Areas`, `Flow`, `Horizontal`, `Vertical`, `Split rows` |
| `Table` | `Column sizes`, `Column align`, `Gap`, `Split rows` |
| `Columns` | `Count`, `Min column width`, `Gap`, `Separator`, `Separator color`, `Balance` |
| `List` | `Marker`, `Marker image` |
| `List item` | `Marker image`, `Trim margins` |
| `Image` | `Fit`, `Side`, `Clear` |
| `Barcode` | `Format`, `Error correction`, `Quiet zone`, `Side`, `Clear` |
| `Figure` | `Caption position`, `Figure counter`, `In table of contents`, `Side`, `Clear` |
| `Heading 1` to `Heading 6` | `In table of contents`, `Clear` |
| `Paragraph` | `Drop cap`, `Clear` |
| `Text` | `Clear` |
| `Block` | `Isolate margins`, `Trim margins`, `Side`, `Clear` |
| `Frame` | `Isolate margins`, `Trim margins` |
| `Cell` | `Trim margins` |
| `Markdown` | `Bullet markers`, `Number markers`, `Table columns`, `Clear` |
| `Table of contents` | `Levels`, `Leader` |
| the element of an `Item` | `Grow`, `Shrink`, `Base size` |

- **They apply like the groups**: with the same [priority](#priority), property by property, and without inheritance.
  What the element declares wins over all its rules.
- **Only what the element can declare.** A rule that gives an element a property it does not have (a `Gap` to a `Text`)
  is `STYLE_NOT_ALLOWED`, with the line of the property in the rule. In `For element` the error comes when the rule is
  read, even if it applies to no element; in `For style` and `For id`, when it is applied, because the same name can go
  on elements of different types. The position rules of a cell, `For column`, `For element: Document` and the generated
  elements (`Code block`, `TOC 1` to `TOC 6`, `Footnotes`) allow none, and neither does a rule that reaches a `Section`.
- **The value is checked when the rule is read.** In `For style` and `For id` it has to be valid in one of the elements
  that have the property: `Gap: 1 2 3` is `VALUE_NOT_ALLOWED` in any case, and `Horizontal: justify`, which is valid in a
  `Stack`, is an error when it is applied to a `Grid`. What depends on the element is checked when the rule is applied:
  the `Column align` of a rule has one alignment per column of each table it reaches (`TABLE_COLUMN_ALIGN`).
- **`Horizontal` and `Vertical`** are those of the `Stack` or the `Grid`, never those of the `Item` or the `Area` that
  wraps the element: the alignment of an item is written in its `Item` or its `Area`.
- **`Grow`, `Shrink` and `Base size`** are of the `Item` ([Stack](../components/stack.md#item)), which is not a box: the
  rule of the element the `Item` wraps gives them, and what the `Item` declares wins over the rule. To an element that is
  not in an `Item` (also that of an `Area`) they are `STYLE_NOT_ALLOWED`.
- **`Marker` and `Column sizes`** are required in a `List` and in a `Table`, and they can come from a rule. Without
  either, the error is `LIST_MARKER_MISSING` or `TABLE_COLUMN_SIZES_MISSING`, with the line of the element.
- **Not in a rule** are the properties of identity, content, structure and position: `Id`, `Style`, `Link`, `Alt`,
  `Span`, `Row header`, `Start`, `Number`, `Pdf page`, `Of`, `Offset`, `Layer`, `Pages`, `Rotate` and `Rotate origin`,
  those of `Section` and `Page`, and the value or the `Content` of an element. The schema does not allow them.

> **Decision:** rules allow the element properties of appearance and distribution, and the engine checks that the
> element can declare them, because the schema cannot: the type goes in the value of `For element`, and in `For style`
> and `For id` it is not known until the rule is applied. *Rejected alternative:* rules that only allowed the groups,
> which made each element repeat the same `Gap` or the same `Fit`.

> **Decision:** a property that the element cannot declare is an error, also in `For style`. *Rejected alternative:*
> ignoring it, which would allow using the same style on elements of different types at the cost of not reporting a
> typo.

> **Decision:** `Grow`, `Shrink` and `Base size` come through the rule of the element the `Item` wraps, and in a rule
> `Horizontal` and `Vertical` are those of the `Stack` or the `Grid`. *Rejected alternative:* allowing `Style` in `Item`
> and `Area`, which are not boxes, and which would make `Horizontal` and `Vertical` ambiguous in a `Stack` that is also an
> item of another one.

> **Decision:** identity, content, structure and position stay out, like the decision on `Offset` and `Rotate`
> ([Layers and rotation](layers-and-rotation.md)). `Row header` too: a `For column` reaches the cells of `Header rows`,
> where it is an error (`ROW_HEADER_IN_HEADER_ROWS`). *Rejected alternative:* all the properties of the element except
> `Id` and `Style`.

> **Decision:** `Marker` in `List` and `Column sizes` in `Table` are no longer required by the schema and the engine
> requires them, so that they can come from a rule. *Rejected alternative:* keeping them required in the element, so
> the rule would never have an effect.

## Nested rules

A rule written inside another applies to the elements it names that are **inside** an element the outer one applies
to, at any depth:

```
Styles:
    For style: card
        Box:
            Background: #FBF8F3
        For element: Image
            Box:
                Width: 100%
                Height: 205
        For style: body
            Box:
                Padding: 10
Block:
    Style: card
    Frame:
        Image: photos/chair.jpg
    Block:
        Style: body
Image: photos/room.jpg
```

The photo of the card is 205 high and the `body` block has its padding; the photo outside does not change.

- **What contains and what goes inside.** `For style`, `For id` and the `For element` of an element written in the
  document, `Section` included, contain rules. Inside go `For element` (also the cell positions, `Header cell`,
  `Body cell`...), `For style` and `For column`. One level: a rule inside another, not inside a nested one
  (`STYLE_NESTED_TOO_DEEP`). `For element: Document`, the cell position rules, `For column` and the rules of the generated
  elements (`Code block`, `TOC 1` to `TOC 6`, `Footnotes`) contain no rules, and `For element: Document`, `Section`,
  `TOC 1` to `TOC 6` and `Footnotes`, which are never inside an element, do not go inside one (`STYLE_NOT_ALLOWED`);
  `Code block` does, since it is inside its `Markdown`.
- **What "inside" is.** The ancestors of the element as written: the `Section`, the elements and the `Row` of a cell,
  with their `Style` and their `Id`. `Item` and `Area` neither count nor get in the way. What a `Markdown` generates is
  inside the `Markdown`; a `Footnote` is where it is written, even though it inherits from the footnote area; the
  entries of a `Table of contents` and the `Footnotes` area are built apart by the engine and take only loose rules.
- **Priority.** The levels do not change: a nested rule is of the level of its own selector (a `For element` inside a
  `For style` is still a `For element`) and, **within each level, it goes after the loose one**, so it wins. Between two
  nested rules of the same level that reach the same element, the one of the **closest ancestor** wins; with the same
  ancestor, the one later in `Styles`, with the sources as always (the document after the styles documents). A loose
  `For style` still wins over a nested `For element`.
- **The cell rules** nested in the rule of a `Table` (`For style: pricing` → `For element: Header cell`) style the cells
  of that table; the loose ones, those of every table ([Table](../components/table.md#cell-style)).
- **The element properties** are given by a nested rule as by a loose one: `For style: dish` → `For element: Block` →
  `Grow: 1` gives the `Grow` to the `Block` that each `Item` of the dishes wraps.
- **A `Style` name whose only rule is nested** is valid only inside its context: outside it is `STYLE_WITHOUT_RULE`, with
  the line of the `Style`, so that a misplacement does not go unnoticed. With a loose rule of the same name it is valid
  anywhere, and inside the context both apply.
- **Styled runs** `[text]{name}` take the nested rules of their context too, in the same order; a rule nested in the
  rule of the run does not apply to the run.
- **Repetition.** The same selector twice inside the same rule and the same source is `STYLE_DUPLICATE`; the same
  selector in two different rules, or loose and nested, is not.
- The errors of a nested rule point to its line, and those of a separate styles document say so.

> **Decision:** scope, not selectors: nesting says "inside" with the same nodes, without combinators or new syntax, and
> the priority stays fixed. *Rejected alternative:* compound selectors with computed specificity.

> **Decision:** between two nested rules the one of the closest ancestor wins, as in typographic inheritance, and the
> order of `Styles` only breaks ties: the result does not depend on where each rule is in the file. *Rejected
> alternative:* the order of `Styles`.

> **Decision:** one level of nesting. *Rejected alternative:* any depth; opening it is easy and closing it is not.

> **Decision:** "inside" means the ancestors of the document, with the generated cases stated one by one. *Rejected
> alternative:* the box tree, in which `Section`, `Row`, `Item` and `Area` do not exist and the generated elements hang
> elsewhere.

> **Decision:** a style with only nested rules is an error outside its context. *Rejected alternative:* valid anywhere,
> like a rule that applies to nothing.

## Named colors

`Named color`, a repeatable child of `Styles`, gives a name to a color: the name and the color go separated by a space.
From then on the name is written wherever a color goes, in the rules and in the elements: `Color`, `Border color`,
`Background` (also inside `linear(...)`) and `Separator color` ([Values](values.md#colors)).

```
Styles:
    Named color: brand #12315A
    Named color: mist #EEF3F8
    For element: Heading 1
        Typography:
            Color: brand
    For style: panel
        Box:
            Background: mist
            Border: 0 0 0 3
            Border color: brand
Text: A note on a light background.
    Style: panel
    Box:
        Background: linear(180, mist, #FFFFFF)
```

- **The name** is written in lowercase, with letters from `a` to `z` and digits, starts with a letter and joins its
  words with a hyphen: `brand`, `dark-gray`, `gray-2`. `linear` cannot be a name.
- **The color** is a hexadecimal color, with its opacity if it has one (`#12315A80`). It cannot be another name or a
  gradient.
- **The order does not matter**: a rule can use a name declared later in `Styles`.
- **A name is replaced by its color when the document is read.** The result is the same as with the color written in
  its place, and the messages that cite a color (such as that of `CONTRAST_LOW`) give its hexadecimal value.
- **The document wins over the separate styles document.** The names of the two sources form a single set; if both
  declare the same name, the color of the document applies, also in the rules of the separate styles document. Within
  one source, a repeated name is `COLOR_DUPLICATE`. Among several separate styles documents, the one passed later wins
  ([Several styles documents](#several-styles-documents)).
- A color with the form of a name that no `Named color` declares is `COLOR_UNKNOWN`, with the line of the property. A
  `Named color` that is not used is not an error.

> **Decision:** one `Named color` node per color, repeatable. *Rejected alternative:* a `Colors >>` block with one line
> per color, which the schema cannot validate line by line.

> **Decision:** a document can change a color of its separate styles document by declaring the same name, and the change
> reaches all the rules that use it. *Rejected alternative:* each rule taking the names of its own source, which would
> force copying the rules to change a color.

> **Decision:** only hexadecimal colors have names. *Rejected alternative:* a name defined with another name or with a
> gradient, which adds chains and cycles without a clear need.

## Priority

Each property takes, from strongest to weakest:

1. what the element itself declares;
2. the `For id` rule of its `Id`;
3. the `For style` rules of its styles (if several declare the same property, the one that comes **later in `Styles`**
   wins, not the order of `Style`);
4. the `For style` rules of the styles of the `Row` of a cell, with the same ordering criterion (the `For id` rule of the
   `Id` of its `Row` goes between points 2 and 3);
5. the `For column` rules of the column of a cell, with the same ordering criterion;
6. the position rules of a cell (`Header cell`, `Body cell`, `Footer cell`, and then `Odd row cell` or
   `Even row cell`);
7. the `Column align` of its table, only for `Align`;
8. the `For element` rule of its type;
9. what is inherited (only `Typography`): for a cell, that of its `Row` and, if not, that of its parent;
10. the default value.

The rules of points 4 to 7 only apply to the cells of a `Table` ([Table](../components/table.md#cell-style)).
The [element properties](#element-properties) follow the same order, without point 9: they are not inherited. For
`Grow`, `Shrink` and `Base size`, what the `Item` declares is point 1. The [nested rules](#nested-rules) are of the
level of their selector and, within it, go after the loose ones; among several, the one of the closest ancestor wins.

A rule wins over inheritance: with `For element: Text` and `Size: 10`, a `Text` measures 10 even if its parent declares
`Size: 20`. Rules are merged **property by property** and not by group: if the rule declares `Size` and the element
`Bold`, both apply. What a rule gives an element in `Typography` is inherited by its descendants, as if the element had
declared it. `Item` and `Area` are not boxes: the rules apply to the element they wrap. The `Style` and the `Id` of a
`Row` apply their rules to each of its cells and not to the strip of the row. `Header rows`, `Body`, `Footer rows` and
`Row` cannot be named in `For element` (the position rules are there to style the cells of each group). `Table` and
`Cell` can. Only `Typography` reaches a `Section` ([Document](../components/document.md#section)).

> **Decision:** fixed priority instead of computed specificity, also with the nested rules, which add a step within each
> level and not a specificity. *Rejected alternative:* computed specificity and compound selectors, more powerful but
> less predictable.

## Validation

What a rule contributes is validated the same as if the element declared it ([Errors](errors.md)), and the error points to
the line of the property inside the rule. The values of a rule are checked even if it does not apply to any element.
These are errors:

- a `For element` that names neither a box element, a generated element nor a position in a table
  (`STYLE_UNKNOWN_ELEMENT`);
- a `For column` that is not a number (`VALUE_SYNTAX`) or a range that does not go from lowest to highest
  (`VALUE_NOT_ALLOWED`);
- two rules with the same selector in the same source and at the same level (loose, or inside the same rule), also
  two `For column` with the same range (`STYLE_DUPLICATE`);
- a rule inside a nested rule (`STYLE_NESTED_TOO_DEEP`);
- a rule nested in one that cannot contain rules (`For element: Document`, a cell position, `For column`, a generated
  element) or that names what is never inside an element (`Document`, `Section`, `TOC 1` to `TOC 6`, `Footnotes`)
  (`STYLE_NOT_ALLOWED`);
- a rule that gives `Break` to an element that does not allow it: `Overlay`, `Page overlay`, a heading, a `Text` of a
  heading or a cell, also with a position rule, a column rule or a rule of the style of its `Row` (`STYLE_NOT_ALLOWED`);
- a rule that gives a `Section` something that is not `Typography` (`STYLE_NOT_ALLOWED`);
- an element property that the element cannot declare: in `For element`, when the rule is read; in `For style` and
  `For id`, when it is applied; also `Grow`, `Shrink` or `Base size` to an element that is not in an `Item`
  (`STYLE_NOT_ALLOWED`);
- an element property with a value that is not valid in any element that has it (`VALUE_SYNTAX`,
  `VALUE_NOT_ALLOWED`);
- a `Style` name or the name of a styled run without its `For style` rule, or with only a nested one outside its
  context (`STYLE_WITHOUT_RULE`);
- the rule of a styled run that declares something a run does not accept, such as `Size`, a `Box` or an element
  property (`STYLE_NOT_ALLOWED_IN_RUN`);
- two `Named color` with the same name in the same source (`COLOR_DUPLICATE`);
- a color with the form of a name that no `Named color` declares (`COLOR_UNKNOWN`);
- a `Named color` without a name and a color separated by a space, with a misspelled name or with a color that is not
  hexadecimal (`VALUE_SYNTAX`), or with the name `linear` (`VALUE_NOT_ALLOWED`).

A `For element`, a `For style`, a `For id` or a `For column` that do not apply to any element are not errors: this way the
rules can be reused, and an element with that `Id` or that style can come later (from a template, for example).

> **Decision:** a rule by type can give an error in a specific element (a `Margin: auto` that does not center in a `Stack`
> item), with the line of the rule. *Rejected alternative:* ignoring what has no effect when it comes from a rule.

## The base typography

`Document` does not allow `Typography`: what all the descendants inherit (usually `Font` and `Size`, which have no default
value) is declared in the `For element: Document` rule, which only allows `Typography` (with `Box` or `Break`, or with
`Language`, it is `STYLE_NOT_ALLOWED`):

```
Styles:
    For element: Document
        Typography:
            Font: IBM Plex Sans
            Size: 10
```

It is the base of inheritance: the `For element` rule of a type or what a box declares changes it for that box and its
descendants.

> **Decision:** the base goes in a rule and not in `Document`, so that it is with the rest of the style and can be moved to
> the separate styles document.

## Separate styles document

The rules and the named colors can be written in a separate document, with root `Styles` and the namespace
`dev.stxt.pdf`, to take them out of the main document or share them among several:

```
Styles (dev.stxt.pdf):
    Named color: brand #12315A
    For element: Document
        Typography:
            Font: IBM Plex Sans
            Size: 10
    For style: panel
        Box:
            Padding: 10
            Border: 0 0 0 3
            Border color: brand
```

- **It is passed at layout time, never looked up.** The document does not say where its styles document is and the engine
  does not look for files or folders: the caller reads it and passes it along with the document
  ([Using from Java](../implementation/api.md#separate-styles)). It is optional, and there can be
  [several](#several-styles-documents).
- **It is weaker than the document.** The same rules are allowed as in the `Styles` of the document. At each priority
  level (that of `For id`, that of `For style`, that of `For element`, etc.), the rules of the separate styles document go
  **before** and those of the document **after**, so the document wins, property by property. The priority between levels
  does not change: a `For style` of the separate document still wins over a `For element` of the document. With this,
  moving the `Styles` of a document to a separate file does not change the result. Named colors follow the same rule:
  if both sources declare a name, the color of the document wins ([Named colors](#named-colors)).
- **Each source is strict on its own.** Two rules with the same selector are an error within one source
  (`STYLE_DUPLICATE`), like two `Named color` with the same name (`COLOR_DUPLICATE`), but the same rule or the same name
  can be in both. A `Style` name can have its `For style` in either of the two.
- **Errors.** A rule of the styles document is validated like one of the document, and its error carries the line **of
  that file** and says so: `line 8 of the styles: ...`. A root that is not `Styles` is `DOCUMENT_ROOT`. A property that
  comes from a rule of the styles document keeps its line in it, also the typography that is inherited, so the same holds
  for the errors seen when applying it or when laying out (a font that does not exist, an overflow). If a message names
  another line, it also says which document it belongs to: `line 8 of the styles: Min width is greater than Max width
  (line 10)`.

> **Decision:** the priority between the two sources is by level, so moving the `Styles` to a file changes nothing.
> *Rejected alternative:* all the rules of the file being weaker than any rule of the document.

> **Decision:** the document does not name its styles document: the caller passes it. *Rejected alternative:* a
> `Styles file` property in `Document`.

### Several styles documents

Several separate styles documents can be passed with a document, in an order. The first one:

```
Styles (dev.stxt.pdf):
    Named color: brand #12315A
    For element: Heading 1
        Typography:
            Size: 20
            Color: brand
```

And the second one:

```
Styles (dev.stxt.pdf):
    Named color: brand #A32D2D
    For element: Heading 1
        Typography:
            Size: 16
```

A `Heading 1` measures 16 and its color is `#A32D2D`: the size and the color of `brand` are those of the second one, and
only the first one declares `Color`.

- **The one passed later wins.** At each priority level the rules of the first styles document go first, then those of
  the second one, and so on up to the last one; those of the document go at the end. If several declare the same
  property at the same level, that of the last one applies, and the document wins over them all. The priority between
  levels does not change: a `For style` of the first one still wins over a `For element` of the last one.
- **The result is that of a single styles document** with the rules of all of them, one after another in that order.
  So splitting a styles document into two that are passed in the same order does not change the result.
- **Named colors** follow the same rule: the names of all of them form a single set and, if several declare a name, the
  color of the last one applies, also in the rules of the earlier ones.
- **Each one is strict on its own.** A repeated rule or name is an error within one styles document (`STYLE_DUPLICATE`,
  `COLOR_DUPLICATE`), not between two.
- **Errors.** With several styles documents, the message says which one the line belongs to, by the place in which it
  was passed: `line 8 of styles 2: ...` is line 8 of the second one. With a single one, the message is
  `line 8 of the styles: ...`.

> **Decision:** among the separate styles documents the one passed later wins, the same criterion as among the rules of
> a `Styles` and as between the separate styles document and the document. *Rejected alternative:* the same rule in two
> styles documents being an error, which prevents having common styles and changing part of them in another styles
> document.

> **Decision:** in the errors, a styles document is named by the place in which it was passed. *Rejected alternative:*
> giving it a name when passing it, more API for what the caller already knows: what was passed and in which order.

## What is not supported

- Compound selectors (several styles at once, the sibling, the direct child), combinators or priorities declared by
  the author. "Inside" is written by [nesting rules](#nested-rules).
- Properties of identity, content, structure or position in a rule ([Element properties](#element-properties)).
- Style of a table row with `Box` or of a whole column: it is given to the cells ([Table](../components/table.md#what-is-not-supported)).
