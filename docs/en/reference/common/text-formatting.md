# Text formatting

What changes how the text of a box looks without changing its box: formatted runs, inline formatting, styled runs,
superscripts and subscripts, capitalization, small caps, letter spacing, ligatures, preformatted text and underline and strikethrough lines. All of them are properties of
[`Typography`](typography.md): **they are inherited** and they are valid in `Styles` rules.

## Runs

Text can have formatted parts within the same line: **bold**, *italic*, underline and strikethrough,
which can be combined. Each part is a **run**. They are written with `Markup: markdown` (below) or generated by a `Markdown`.

- Each run uses its variant of the font, which must exist (`FONT_VARIANT_MISSING`, with the line of the run) and have its
  characters (`GLYPH_MISSING`). Bold and italic are **added** to those of the box: they cannot be removed. A bold run
  has weight 700, or that of the box if it is already 700 or more (`Weight`, [Typography](typography.md#weights-weight)):
  in a text of weight 300 bold is 700, and in one of 900 it stays 900.
- Size and `Line height` are those of the box, so lines do not change height. Color and family too, except in code,
  which uses `Code font` ([below](#inline-code)), and in a [styled run](#styled-runs). A superscript and a subscript
  are painted smaller within their line ([below](#superscript-and-subscript-position)).
- A word with parts from several runs (**bo**ld) is a single word: it is not split between them and it measures the sum of
  its parts.
- The space between two words has the formatting of the run of its first white space character: an underline covers the spaces
  inside its run, but not the one between two runs that do not carry it. With `justify`, the extra space belongs to the run
  of its space.
- A run can carry the target of a link ([Links](links.md)), which changes neither how it is measured nor how it looks.
- A run can be an image ([below](#images-inside-a-text)).

> **Decision:** a run is a set of marks and not a weight and a style of its own: this way `Styles` can change the font
> of the box without touching the runs. *Rejected alternative:* runs with explicit `Bold` and `Italic`, which could undo
> the style of the box.

> **Decision:** the bold of a run is 700, unless the box is already heavier. *Rejected alternative:* the next weight
> the family has above that of the box, which would make the bold of a text change when a file is added to the fonts
> folder.

## Inline formatting (`Markup`)

By default the text of a `Text`, a `Paragraph` or a `Cell` is **literal**: asterisks are asterisks. With
`Markup: markdown` it is interpreted as the inline Markdown of a [`Markdown`](../components/markdown.md), with the same
syntax: `**bold**`, `*italic*`, `++underline++`, `~~strikethrough~~`, `` `code` `` ([below](#inline-code)),
`[text](target)` ([Links](links.md)), `[text]{name}` ([below](#styled-runs)) and the call of a footnote, `[^id]`, which
is a superscript run with the number of the note ([Footnote](../components/footnote.md)).

- Marks are not text: they are neither measured nor painted. A special character is written with a backslash in front (`\*`, `\[`,
  `\\`).
- A single line break in `Content` counts as a space, and a `\` at the end of the line is a forced line break
  ([Markdown](../components/markdown.md#forced-line-breaks)).
- **It is inherited**: it is declared once in `For element: Document` or in a rule, and a text goes back to literal with `Markup: none`.
- It only interprets formatting within the line. What would start a block in a `Markdown` is text:
  `- 5% off`, `2024. A good year`, `# 1 in sales`, `> 30 years` or a `---` line are painted as they are, without
  escaping them, and a list or a heading is written in a `Markdown`. Within the line, an image or HTML are
  `MARKDOWN_UNSUPPORTED`, with the line of the paragraph, and so is a link with a title or with a target that is not
  accepted, the same as in a `Markdown`.
- It does not act inside a `Markdown`, even if it is inherited (what is escaped is still literal), nor in the entries of a
  `Table of contents`. `Alt` and the other values are always literal.
- References (`{page}`, `{page of: id}`) work the same way.
- The text of the box is the text without marks: it is what a screen reader reads and what a `Table of contents` copies. An error
  in the text (a character the font does not have, an unknown reference) reports the line where the text starts.

> **Decision:** inline formatting is requested with an inheritable property: text is literal unless it is requested, and it is requested
> once. *Rejected alternative:* `Run` children with their own `Typography`, much longer to write.

> **Decision:** block syntax is text and not an error. Since `Markup` is inherited and declared once for the whole
> document, an error would reach any text, cell or heading that starts with a number followed by a period, a hyphen
> or a `#`, and the list of what has to be escaped is long (`-`, `+`, `*`, `1.`, `1)`, `>`, `#`, a `---` or `===` line,
> a list that starts in the middle of a sentence). Whoever writes a list in a text with `Markup: markdown` gets it literally,
> as without `Markup`. *Rejected alternative:* `MARKDOWN_UNSUPPORTED` with the line of the block, which forced escaping the
> first character.

## Styled runs

With `Markup: markdown`, or in a `Markdown`, a text in brackets followed, with nothing in between, by the name of a style
in braces, `[€12.50]{price}`, is a **styled run**: it takes from the `For style: price` rule of `Styles`
([Reusable rules](styles.md)) what changes how its letters look and not the height of the line.

| Property of the rule | In the run |
|---|---|
| `Font`, `Bold`, `Weight`, `Italic` | the family, the weight and the style of its font, which must exist |
| `Code font` | the family of the code inside the run |
| `Color` | the color of its letters and of its lines |
| `Case`, `Small caps` | how its letters are painted ([Capitalization](#capitalization-case), [Small caps](#small-caps-small-caps)) |
| `Letter spacing` | the letter spacing of its characters, also of its spaces ([Letter spacing](#letter-spacing-letter-spacing)) |
| `Position` | the run as a superscript or a subscript ([below](#superscript-and-subscript-position)) |

- What the rule declares **replaces** what the box has, and what it does not declare is that of the box. If two
  `For style` rules with that name (one of the separate styles document and one of the document) declare the same thing,
  the one of the document wins, as in a box.
- **The marks add to the style**, inside or outside the brackets: `[**x**]{light}` and `**[x]{light}**` are bold even
  if the rule says `Weight: 300`, and bold is weight 700 ([above](#runs)). For the marks beside them, the brackets and
  the braces of the run are punctuation, like those of a link, and the rule of CommonMark applies:
  `[**€12.50**]{price}` is bold, and in `H**[2]{sub}**O`, where the asterisks are between a letter and the run, they
  do not open or close and are text. Next to a letter, the marks are written inside: `H[**2**]{sub}O`.

> **Decision:** the brackets and the braces of a run count as punctuation for the marks beside them, like those of a
> link. *Discarded alternative:* that they count as letters (up to 0.17.0), with which `H**[2]{sub}**O` was bold, but
> `[**€12.50**]{price}` painted its asterisks.
- **The name** is a single word, without spaces, the same as in `For style`. Without its rule, it is `STYLE_WITHOUT_RULE`,
  with the line where the text starts. Brackets followed by something else (`[x] {price}`, `[x]{a b}`, `[x]{}`) are text,
  and page numbers and references stay what they are: in `[see]{page}` or `[see]{page of: id}`, the brackets are
  text. That is why `page` and `pages` cannot be the name of a run.
- **A rule that declares something else** (`Size`, `Line height`, `Align`, `Markup`, a `Box` or a `Break`) is
  `STYLE_NOT_ALLOWED_IN_RUN` if it is used in a run, with the line of what it declares. The same rule can style a box
  with `Style`, where everything is valid.
- **Links.** A link can have a styled run in its text (`[[see price]{price}](https://...)`) and a styled run can have a
  link (`[see [here](https://...)]{price}`). A styled run inside another is `MARKDOWN_UNSUPPORTED`, as is one that starts
  in a paragraph, a cell, a heading or a list item and ends in another. Brackets that a blank line separates are text.
- **What is not Markdown text does not form runs**: escaped brackets (`\[x\]{price}`), those inside code, in the
  target of a link or in an image, and those of a code block, which are written as they are.
- An error of the run (a family that does not exist, a low contrast) reports the line of the property in the rule. The
  text that a screen reader reads and that is copied is the written one.
- A text with Markdown cannot have the Unicode noncharacters U+FDD0 to U+FDEF, which the engine uses to mark the styled
  runs: it is `MARKDOWN_UNSUPPORTED`. A noncharacter is not text and no font has it.

> **Decision:** a styled run takes a `For style` rule and has no properties of its own, like `Style` in a box: the look
> is declared once and changed in one place. *Rejected alternative:* attributes in the text (`[x]{color=#B3261E}`), which
> would spread the colors across the document.

> **Decision:** what the rule cannot apply to a run is an error and is not ignored, even if the rule is also used in
> boxes. *Rejected alternative:* taking from the rule only what is valid in a run, which would make `Size` change the box
> and not the run without any warning.

> **Decision:** the Markdown marks add to the style of the run wherever they are written, as they add to the box.
> *Rejected alternative:* the run winning over the marks outside it (`**[x]{light}**` at weight 300), which forces looking
> at the nesting to know how a word looks.

## Superscript and subscript (`Position`)

`Position: superscript` or `subscript`, in the `For style` rule of a [styled run](#styled-runs), makes the run a
superscript or a subscript: `m[2]{sup}`, `CO[2]{sub}`, `1[st]{sup}`, `Brand[TM]{sup}`.

```stxt
Styles:
    For style: sup
        Typography:
            Position: superscript
    For style: sub
        Typography:
            Position: subscript
Paragraph: It emits 120 g of CO[2]{sub} per m[2]{sup}.
    Typography:
        Markup: markdown
```

| `Position` | Size | Baseline |
|---|---|---|
| `normal` (by default) | that of the box | that of the line |
| `superscript` | 70 % of that of the box | raised 0.33 of the size of the box |
| `subscript` | 70 % of that of the box | lowered 0.15 of the size of the box |

- **It does not change the height of the line**, like the call of a footnote ([Footnote](../components/footnote.md#the-call)),
  which has the size and the height of a superscript. The run is measured at its size, so it takes up less width.
- The letters are those of the font, reduced: neither the superscript glyphs of the font nor the Unicode characters
  (`²`, `₂`) are used, and these can still be written if the font has them. The text that is read and copied is the
  one written (`m2`).
- The rule can also declare what a run allows (`Color`, `Font`, `Weight`...), and the marks add to it: `[**2**]{sub}`
  is a subscript in bold.
- **The strikethrough goes with the letters** of the run, at their height and with their thickness. **The underline stays
  on the line**, so that it does not break under a word with a superscript.
- Small caps do not reduce the run further: a letter of a superscript measures 70 % with `Small caps` and without it.
- The call of a footnote inside a subscript is still a superscript.
- **It is only valid in a run.** `Position` in a box, with any value, is `POSITION_OUTSIDE_RUN`, with the line of the
  property: in the `Typography` of an element, in a `For element` or `For id` rule (when the rule is read), and in a
  `For style` rule given to a box with `Style`. `normal` is for a nested rule, so that a run name is not a superscript
  inside an element ([Nested rules](styles.md#nested-rules)).

> **Decision:** the superscript and the subscript are a property of the rule of a styled run and not a new mark of the
> text: Markdown has none, and the document already names its runs. *Alternative discarded:* a syntax of its own
> (`^2^`, `~2~`), which clashes with the strikethrough and would have to be escaped in the texts that use those characters.

> **Decision:** the size and the shift are fixed, those of the call of a footnote, and the subscript goes down 0.15 to
> stay inside the line. *Alternative discarded:* two more properties (size and shift), or `Size` in a run, which would
> open the runs to any size and with them the height of the line.

> **Decision:** `Position` in a box is an error and is neither ignored nor inherited: a whole box as a superscript has no
> line to be raised on. *Alternative discarded:* that the text of the box inherits it, which would mix it with
> `Overflow: shrink` and with the drop cap for no use.

## Inline code

With `Markup: markdown`, or in a `Markdown`, what goes between backticks (`` `mvn test` ``) is **code**: a
run with the family of `Code font`, which keeps the weight and the style of the box and those of the marks of the run
(``**`x`**`` is bold code). Size, color and `Line height` are those of the box, so lines do not
change height, and white space is collapsed as in the rest of the text.

`Code font` belongs to `Typography` ([Typography](typography.md)) and is inherited: it is declared once, in `For element: Document`,
for the whole document. Inside a [styled run](#styled-runs) the `Code font` of its rule applies, if it declares one.
Without any, code is an error (`CODE_WITHOUT_FONT`), with the line where the text starts (in a `Markdown`, that of the
paragraph). If the family does not exist, it is `FONT_UNKNOWN`, with the line of `Code font`.

## Images inside a text

With `Markup: markdown`, or in a `Markdown`, `![alt](path)` inside a text is an **inline image**: an icon in a
sentence, a small logo in a heading. The path is relative to `images/` of the resources folder, like that of an
`Image` ([Image](../components/image.md#file)); only PNG, JPEG and SVG (the page of a PDF is `IMAGE_FORMAT`, and a path
that does not exist, `IMAGE_UNKNOWN`, with the line of the text). Alone in its paragraph of a `Markdown` it is still an
`Image` ([Markdown](../components/markdown.md#the-subset)).

- **It measures as a word.** It is as tall as the size of the line (`Size`; with `Overflow: shrink`, the size the text
  shrinks to) and as wide as its proportion gives; it has no letter spacing. Glued to some letters it forms one word
  with them, which is not broken; between spaces it is one more word, which goes to the next line if it does not fit.
  An image wider than the line overflows, like a word ([Overflow](overflow.md)).
- **It is painted in its place**, centered on the capitals of the font on the baseline, like the image marker of a
  list ([List](../components/list.md#image-markers)). It does not change the height of the line.
- The alternative text is the `Alt` of its `Figure` in the tagged PDF, inside the element of the text, in reading
  order; without it (`![](path)`) the image is decorative, an *artifact* ([The PDF inside](../implementation/pdf.md#figures)).
  It is not part of the text: it is not copied, not searched, and does not appear in the bookmarks or in the running
  heads of a heading.
- Inside a link, `[![alt](path)](target)`, the image is clickable and its `Alt` is what is read of the link. Neither the
  underline of the link nor a strikethrough is painted over an image. The rest of the format of the run (bold, a styled
  run) does not affect it.
- The Markdown title (`![alt](path "title")`) is an error, as in an `Image`.

```stxt
Paragraph: Included ![Yes](icons/check.svg) in every plan.
	Typography:
		Markup: markdown
```

> **Decision:** the image measures what the letters do and is aligned like the image marker, without properties: an
> inline image is an icon, and a size or an alignment of its own would need a syntax Markdown does not have.
> *Rejected alternative:* a height in the `Alt` or in the title, which mixes the measure with the text that is read.

> **Decision:** an inline image is a run whose text is the object replacement character (U+FFFC), which is never
> painted nor read: so it goes through the line breaking, the runs and the links like any other run. *Rejected
> alternative:* an `Image` box inside the inline flow, which required a second line model.

## Capitalization (`Case`)

`Case` changes **what is painted and not what is written**: a label is written as a normal phrase and a rule puts it
in capitals.

- It changes what the text measures (`ß` becomes `SS`), so it is applied before breaking the text into lines.
- `uppercase` and `lowercase` follow the rules of the `Language` of the box (in Turkish, `i` becomes `İ`). `capitalize` raises the
  first letter of each word (what follows a space or a line break, also between two runs) and leaves the rest
  as it is (`iPhone` gives `IPhone`).
- `{page}` and `{pages}` are not transformed.
- A screen reader reads the written text ("Emisor" and not "EMISOR"), except in a text with `{page}`, `{pages}` or a
  reference, where it reads what is painted.
- A [styled run](#styled-runs) with `Case` in its rule uses its own. `capitalize` still looks at what goes before the
  run.

## Small caps (`Small caps`)

`Small caps` paints each lowercase letter, converted to uppercase, at 80% of `Size`. Spaces, digits, symbols and
uppercase letters stay as they are. It is applied after `Case`: with `lowercase` everything is small caps, with `uppercase` nothing is, and with
`capitalize` only the initial is large. The `Size` of the box, the height of the lines and the underline and strikethrough lines do not change. A screen
reader reads the written text, as with `Case`. A [styled run](#styled-runs) with `Small caps` in its rule uses its own.

> **Decision:** small caps are synthesized and not the `smcp` feature of the font, which none of the included fonts
> have. With `Case: uppercase` they have no effect and it is not an error: both are inherited, and it is normal to declare them
> in different places.

## Letter spacing (`Letter spacing`)

Points added to the advance of each character, also the space, **except the last one of each line**, so that `right` and
`center` stay aligned with the last letter. A [styled run](#styled-runs) with `Letter spacing` in its rule carries its own
in each of its characters, and the last one of the line does not carry that of its run. A run with letter spacing has no
ligatures ([below](#ligatures-ligatures)). It counts in line breaking, in intrinsic sizes and in
alignment, and `justify` shares out what is left over afterward. It can be negative, and there is no check that the advance stays
positive. A percentage is `VALUE_NOT_ALLOWED`.

The text that is copied or extracted from the PDF is that of the line, without spaces between the letters
([The PDF inside](../implementation/pdf.md#text-that-is-read)).

## Ligatures (`Ligatures`)

By default each character is a glyph: `fi` is two. With `Ligatures: true` the ligatures of the font are applied, which
join some pairs into a glyph of a different width (in IBM Plex Sans, `fi`; in IBM Plex Serif, `fi` and `fl`; and none in IBM Plex
Mono). What is measured is what is painted. A ligature does not cross a space or the boundary between two runs. With
`Letter spacing` other than 0, that of the box or that of a styled run, there are no ligatures. It changes neither the text that is read nor the text that is copied: in the PDF, the glyph of a
ligature is the letters it joins (`fi`), and not the character the font has for that glyph (U+FB01), which a search for
`office` would not find in every viewer.

> **Decision:** `false` by default: without ligatures a running text is written faster (about 2.7 times; documents
> with little text per page, the same). *Rejected
> alternative:* ligatures always, or never.

## Preformatted text

By default white space is collapsed. With `Preformatted: keep` or `wrap` the text **keeps its spaces and its
line breaks**: each line of the text is a line of the box, also the empty ones. A blank line does **not** separate
paragraphs: the whole text is one paragraph for widows and orphans ([Breaks](breaks.md)), so a long block is
split between lines. It acts in a `Text`, a `Paragraph` and a `Cell` with text. The usual choice is a monospaced font and a
`Content >>`, which keeps the relative indent (not the spaces at the end of a line or the trailing blank lines).
A line break at the end of the text does not add an empty line.

- **`keep`** does not break lines: one wider than the box is `TEXT_OVERFLOW`, with the line of the document where it is.
- **`wrap`** breaks lines that are too wide **between words**, with greedy line breaking. The indent is kept and the
  spaces at the break are lost. A word wider than the box is still an error: in a preformatted text a word is not
  split after a written hyphen, nor cut with `Break long words`
  ([Typography](typography.md#long-words-break-long-words)).
- **Tabs (`Tab size`).** Each tab moves to the next column that is a multiple of `Tab size`, counting from the
  start of the line (with `Tab size: 4`, `a⇥b` is `a   b`, and `abcd⇥e`, `abcd    e`). A value less than 1 is
  `VALUE_NOT_ALLOWED`.
- **Alignment.** `justify` is treated as `left`, because `Align` is inherited and a code block would inherit the error.
  `right` and `center` align each line separately.
- `Case`, `Letter spacing`, runs, `{page}` and references work as always. With `Markup: markdown` the
  text is interpreted first, so the lines that are kept are those of the paragraphs.
- **First line indent.** `First line indent` moves the first line of the text, and only it; with `wrap`, that line
  is broken at what the indent leaves ([Typography](typography.md#first-line-indent-first-line-indent)).
- **Forced line break.** The character U+2028, which is also what the `\` at the end of a line leaves with
  `Markup: markdown`, ends the line like any other line break
  ([Markdown](../components/markdown.md#forced-line-breaks)).
- **Other spaces.** Only the space, the tab and the line breaks are treated as such. Any other white-space character,
  also U+000B and U+000C, stays in its line and the font has to have it (`GLYPH_MISSING`,
  [Typography](typography.md#spaces-and-paragraphs)).

### Intrinsic sizes

With `Preformatted: keep`, the narrowest width and the natural width are the widest line. With `wrap`, the narrowest width is the
widest word and the natural width, the widest line.

> **Decision:** preformatted text is an inheritable property and not an element of its own, which would not fit in a
> `Cell` with a value.

## Underline and strikethrough

A line in the color of the text, across the run (with its spaces, but not with the space between two runs that do not
carry it). Its position and its thickness are those given by the variant of the run, so the bold line is thicker. The
underline goes below the text and the strikethrough, over it. A screen reader does not announce them.

## What is not supported

- Runs with another size (except the [superscript and the subscript](#superscript-and-subscript-position), the call of
  a footnote and the drop cap of a `Paragraph`, [Text](../components/text.md#drop-cap-drop-cap)) or another line
  height, superscripts and subscripts with another size or another shift or with the glyphs of the font for them, styled runs inside others, and marks that
  remove bold or italic (a styled run can, with `Weight` or `Italic: false`).
- Line styles (wavy, dotted), a color of its own for the line, or an underline that skips descenders.
- Full-width `Case`, letter spacing relative to the font size, small caps with `smcp` and more `Preformatted` modes.
- Inline images with another size than that of the letters or aligned otherwise, and the page of a PDF or a barcode
  inside a text.
