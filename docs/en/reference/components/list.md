# `List` and `List item`

A `List` stacks its items (`List item`) vertically, like a `Block`, and each item carries a **marker** generated by the
engine, which is not in the document. Both are block boxes and accept `Id`, `Style`, `Link`, `Box`, `Typography` and
`Break`. An item contains one or more elements, any except headings (a `Paragraph`, a `Text`, a `Block`
or another `List`). An empty item is `LIST_ITEM_EMPTY`. A `List` goes wherever an in-flow element goes, also inside another item.

```
Styles:
    For element: List
        Box:
            Padding: 0 0 0 18
List:
    Marker: decimal
    Start: 3
    List item:
        Paragraph: First point
    List item:
        Number: 10
        Paragraph: Second point
        List:
            Marker: bullet
            List item:
                Text: Subpoint
```

| Property | Values | Default | Elements | Notes |
|---|---|---|---|---|
| `Marker` | `bullet`, `dash`, `none`, `decimal`, `lower-alpha`, `upper-alpha`, `lower-roman`, `upper-roman` | required | `List` | Marker of the items: `•`, `–`, none, or a numbering (`1.`, `a.`, `A.`, `i.`, `I.`). |
| `Start` | integer | `1` | `List` | Number of the first item. Only in the numberings. |
| `Number` | integer | none | `List item` | Number of this item. The following ones continue from it. Only in the numberings. |

They do not go in the `Styles` rules, which only accept the groups. The indent of the items is the left `Padding` of the
`List`.

> **Decision:** a single `List` element with a required `Marker`, which is not inherited: each nested list declares its own.
> *Rejected alternative:* two elements (bulleted and numbered), or `Marker` in `Typography`.

## Markers

`Marker` is required: whether the list is numbered is decided by the author. The marker is text in the typography of the
`List item` (its own, inherited or from `For element: List item`): `•` (`bullet`), `–` (`dash`), none (`none`), or the number of the
item with a period: `3.`, `c.`, `C.`, `iii.`, `III.`. It is always followed by a space, which separates it from the content.

> **Decision:** the marker is text in the font of the item, without a hollow circle or a square, which IBM Plex Sans does not have.
> *Rejected alternative:* drawing them as shapes.

## Numbering

The first item carries the number `Start` (1 if it is not declared). Each one carries the number after the previous one, except the one that sets its own
with `Number`, from which the rest continue. Letters continue after `z` with two letters (`aa`, `ab`). `decimal`
writes from 0, and letters and Roman numerals, from 1. Roman numerals go up to 3999 (`LIST_NUMBER_RANGE`). `Start` and `Number`
only have an effect in the numberings (`LIST_NUMBER_NOT_ALLOWED`). Each list numbers its items, and a nested list starts
again. The number of an item can be referred to with `{number of: id}` ([References](../common/references.md#number-of-id)).

## Position

The marker hangs **outside** the item, to its left: its right edge (with the final space) touches the left edge of
the border box of the item, so markers of different widths are aligned to the right. The indent that holds it
is the left `Padding` of the `List`, plus the left margin of the item. Its baseline is that of the **first line** of the
item: the one found by going down through the first in-flow child of each block until a text is reached (with a nested list at the
start, both markers are on the same line).

- An item with a marker whose content does not lead to a text in this way (it starts with a `Stack`, a `Grid`, an `Image` or an empty
  block) is an error (`LIST_ITEM_WITHOUT_LINE`), on the line of the box that prevents it.
- So is a marker wider than its indent (`LIST_MARKER_OVERFLOW`): it does not stick out of the list.

> **Decision:** there is no indent property and no fixed marker width: the indent is the `Padding` of the `List`.
> *Rejected alternative:* an `Indent` property, or aligning the marker with the top edge of the item.

## Breaks

The marker is attached to the first line: if it does not fit in what remains of the page, both move to the next one, and if the item
breaks, the marker is only in its first fragment. It does not change the break rules ([Breaks](../common/breaks.md)).

## Accessibility

A screen reader announces the list with its number of items, and each item with its marker.

## What is not supported

- Markers inside the item, with a style of their own different from the item, with images or with other text.
- Hollow circle and square.
- Lists in reverse order and suffixes other than the period.
